# 雾航司机 脚本架构设计

Oct 6, 2026 · @Charlie

## 1. 目标与约束

本文件规定 `Assets/Scripts` 的分层、目录、程序集和配置方式。玩法以《Fogline Driver v6.1》为准，demo 范围以 `mvp_demo_plan.md` 为准。

**要解决的问题：**

雾航司机的核心是一个**连续运行的模拟**（列车物理、潮汐、声音传播、猎手），而且同一套模拟要被重复使用：

| 用途 | 要求 |
| --- | --- |
| 实时游玩 | 按固定步长推进 |
| 时间轴预测、航线算账 | 用同一套函数算未来某时刻的潮位、深度、能耗 |
| 平衡检查测试 | 在 EditMode 里不开场景直接跑 |
| 失败重来 | 给整个世界拍快照并恢复 |
| 试玩日志 | 记录玩家的指令序列 |

因此模拟必须**不依赖场景和 MonoBehaviour**。

**要避免的问题：**

面包店项目早期把很小的概念各自拆成目录和配置（例如每个枚举一个文件夹、每个小领域一个 Config），之后目录和配置无限增长。本项目反过来：

- **分层少而固定，同一层内的各部分范围大致相当**，像集合的一个划分：互不重叠，合起来覆盖全部，大小势均力敌。
- 新内容**优先放进已有的部分**，而不是开新目录、新配置。

## 2. 总体分层

六层，依赖只能从上往下：

```
Editor   编辑器工具
Tests    EditMode 测试
   ↓
View     表现：海图、驾驶舱、站台
   ↓
Game     应用外壳：启动、服务、全局状态机、模拟驱动
   ↓
Sim      纯模拟：雾海、线网、列车、海图
   ↓
Core     通用基础设施：EventBus、StateMachine、MonoSingleton、通用数学
```

| 层 | 职责 | 可以依赖 | 禁止 |
| --- | --- | --- | --- |
| **Core** | 与本游戏无关的通用工具 | UnityEngine | 任何游戏概念 |
| **Sim** | 世界状态、规则、配置定义 | Core、UnityEngine 的数学与 ScriptableObject 类型 | MonoBehaviour、GameObject、`Time.*`、场景、ServiceManager、EventBus |
| **Game** | 把模拟接进 Unity：启动、输入、存档、日志、全局状态机 | Sim、Core | 直接画东西 |
| **View** | 把状态画出来、播出来，把操作交给 Game | Game、Sim（只读）、Core | 修改 Sim 状态（只能通过指令） |
| **Tests** | EditMode 测试 | Sim、Core（必要时 Game） | — |
| **Editor** | Inspector、关卡编辑工具、检查窗口 | 全部 | 进入构建 |

每一层是一个 **asmdef**（`Fogline.Core`、`Fogline.Sim`、`Fogline.Game`、`Fogline.View`、`Fogline.Tests`、`Fogline.Editor`），依赖方向由编译器保证，不靠约定。

Sim 允许引用 UnityEngine，以便使用 `Vector2`、`Mathf` 和 ScriptableObject 类型；上表的禁止项由一条 EditMode 测试扫描 Sim 程序集来保证。

## 3. Sim 层：四个领域

Sim 按游戏世界本身的四个组成部分划分，与 v6.1 第 2.1 节对应：

| 领域 | 范围 | 包含的规则 |
| --- | --- | --- |
| **Sea 雾海** | 连续空间，以及其中的一切 | 高度图采样；潮汐 `L(t)` 与深度、雾压；谷地水道与潮流；声源登记、距离衰减与地形遮挡；投放物落地后的声源；猎手（听觉、警觉值、最后听见的位置、行为阶段、硬直、搁浅、攻击） |
| **Network 线网** | 嵌在雾海里的图 | 节点与边、段；结构由高程推导；建设状态与已铺长度；轨道等级与限速；缺陷；道岔；施工造价；站点（配额、监听和广播半径、播出时段）；委托 |
| **Train 列车** | 玩家的车 | 操纵件与列车子状态（熄火、行驶、滑行、铺轨、改造……）；受力与沿边移动；能源、噪音、雾压与耐压；车厢格子与物品；发射器与装填；施工操作 |
| **Chart 海图** | 玩家知道的一切 | 被动和主动声纳；接触目标三级与三角定位；勘测层与旧地图比对；标记（时间、来源、可信度、褪色）；观测者、通告队列、转播与接收；航线估算器（距离、能耗、最深点、到达潮位） |

**划分依据：**

- 前三个是"世界里有什么"，海图是"玩家知道什么"。v6.1 第 3.1 节已经把世界和认知分开，这里沿用同一条线。
- 四个领域的规模大致相当，预计各有 8–12 个文件。

**归属规则**（遇到拿不准的东西时）：

| 东西 | 归属 | 理由 |
| --- | --- | --- |
| 猎手 | Sea | 它在连续雾海里移动，不受轨道约束 |
| 主动声纳 | 发射动作归 Train；扫描结果归 Chart | 发射是车的操作，回波是知识 |
| 声诱饵 | 发射归 Train；落地后发声归 Sea | 落地后它就是雾海里的一个声源 |
| 站点、委托 | Network | 站点是图上的节点，委托是节点之间的运输 |
| 观测者的监听与广播 | Chart | 它们产生的是情报 |
| 施工造价 | Network；施工操作归 Train | 造价是边的属性，施工是车的行为 |

**领域之间的依赖**（无环）：

```
Sea ← Network ← Train ← Chart
```

- Sea 不知道列车存在。列车通过 Sea 的声源登记接口"发出声音"，猎手只听声源。
- 猎手攻击等跨领域结果，以事件的形式返回，由 `SimWorld` 应用到列车上。

**Sim 根目录只放四个文件：**

| 文件 | 内容 |
| --- | --- |
| `SimWorld.cs` | 聚合四个领域的状态；`Tick(dt, 指令)` 按固定顺序推进；`Clone()` 用于快照 |
| `SimClock.cs` | 游戏时间与时间比例 |
| `Commands.cs` | 全部玩家指令（拨手柄、扳道岔、点火、施工、发射、选弹种、装填、使用物品……） |
| `ScenarioSO.cs` | 关卡内容资产（见第 5 节） |

**每一步的推进顺序：**

1. 应用本步的指令。
2. Sea：推进时间、潮汐与潮流。
3. Train：受力、移动、施工（改写 Network 的状态）、能源与噪音，并把声源登记到 Sea。
4. Sea：猎手听、想、动；产生攻击、硬直等事件，由 `SimWorld` 应用。
5. Chart：声纳、接触目标、观测、广播、标记褪色。
6. 返回本步的事件列表。

## 4. 数据流

```
键盘/鼠标 → Game.Input → 指令
                           ↓ 排队
            Game.SimRunner：固定步长（初始值 20 Hz）调用 SimWorld.Tick
              ↓ 连续量                          ↓ 离散事件
   View 每帧直接读状态并插值          SimRunner 转发到 EventBus → View 订阅
   （位置、速度、能源、手柄）         （发波、发现目标、收到通告、硬直、货损……）
```

- **连续量不发事件**，View 每帧直接读，避免每帧几百个事件。
- **离散事件**沿用 Core 的 EventBus 和 EventSubscriber，写法与面包店相同。
- **指令**同时写进试玩日志。
- **快照**：停靠时 `SimWorld.Clone()` 存进内存；能源归零时恢复。完整游戏的存档序列化同一份状态。

## 5. 配置与内容

ScriptableObject 只有两种用途：**调参**和**内容**。SO 的类定义（`.cs`）放在它所属的 Sim 领域里，例如 `SeaTuningSO` 在 `Sim/Sea/`，`ItemSO` 在 `Sim/Train/`，`ScenarioSO` 在 Sim 根目录；资产文件（`.asset`）放在 `Assets/Data/`。

### 5.1 调参：每个领域一个

| 资产 | 内容 |
| --- | --- |
| `SeaTuningSO` | 世界（雾面高度、潮汐、时间比例、雾压换算）；声音（衰减、遮挡、各类噪音）；猎手（阈值、速度、听觉、警觉值、硬直与习惯、攻击） |
| `NetworkTuningSO` | 段长、结构判定阈值、各结构的造价、各等级的限速与噪音、弯道限速、缺陷的撞击阈值 |
| `TrainTuningSO` | 质量、牵引力、制动级位与再生效率、重力系数、能源与各项消耗、耐压、车厢格子尺寸、速度、发射器 |
| `ChartTuningSO` | 被动和主动声纳、测向仪、标记褪色时间、广播覆盖、预测模糊度 |

- 每个调参资产内部用 `[Serializable]` 小节分组，在 Inspector 里折叠显示。
- **新参数一律加进对应领域的调参资产**，作为新字段或新小节，不新建 SO 类型。

### 5.2 内容：只有两类资产

| 资产 | 内容 | 数量 |
| --- | --- | --- |
| `ScenarioSO` | 一张关卡的全部内容：高度图、谷地水道、节点与边（曲线、隧道和桥的区段、初始建设状态、已铺长度、等级）、缺陷、旧地图的差异、站点、委托、猎手的出生位置、开局物品 | demo 只有一个：林芝 |
| `ItemSO` | 一种物品：类别、尺寸、重量、标签、效果参数 | 每种物品一个 |

- 站点和委托写在 `ScenarioSO` 内部的列表里，不单独做资产，因为它们只属于这一张关卡。
- **新增 SO 类型的门槛**：只有"会有很多个实例、并且被多处引用"的内容才能成为新的资产类型。
- 运行时会变的东西（已铺长度、道岔指向、配额剩余）全部复制进 `SimWorld`，**绝不写回 SO**。

## 6. 目录

```
Assets/
├── Data/                      # 只有 .asset，没有 .cs
│   ├── Tuning/                # 四个调参资产
│   ├── Items/                 # 每种物品一个 ItemSO
│   └── Scenarios/             # 每张关卡一个文件夹：ScenarioSO + 高度图
└── Scripts/
    ├── Core/                  # 平铺，不分子目录
    ├── Sim/
    │   ├── Sea/
    │   ├── Network/
    │   ├── Train/
    │   ├── Chart/
    │   └── （SimWorld、SimClock、Commands、ScenarioSO）
    ├── Game/                  # 平铺
    ├── View/
    │   ├── Chart/             # 海图渲染：图层、视图、等高线、雾的着色
    │   ├── Cockpit/           # 驾驶舱 3D、仪表、手柄动画、车厢格子界面、音效
    │   └── Station/           # 站台界面（UI Toolkit）
    ├── Tests/                 # 平铺
    └── Editor/                # 平铺
```

### 6.1 各部分的内容

| 部分 | 内容 |
| --- | --- |
| **Core** | EventBus、EventSubscriber、StateMachine、IState、MonoSingleton、通用几何与采样工具（沿线采样、marching squares 等高线提取、曲线弧长参数化） |
| **Game** | Bootstrap、ServiceManager、GameManager 与全局状态（Boot、MainMenu、Station、Transit、GameOver）、SimRunner、输入到指令的映射、快照、试玩日志、问卷 |
| **View/Chart** | 四个图层、三个视图、等高线网格、雾的深度着色 shader、安全等深线、洋流箭头、发射器预览、时间轴、航线规划交互 |
| **View/Cockpit** | 驾驶舱外壳、仪表、手柄动画、车厢格子界面、按键提示、三维音效 |
| **View/Station** | 合并后的站台界面：委托、装载、海图台 |
| **Tests** | 各领域规则测试、平衡检查测试、Sim 程序集禁止项扫描 |
| **Editor** | 轨道编辑工具（在 Scene 视图里叠着高度图摆节点、画曲线）、高度图检查窗口（每条边在三个潮位下的深度和坡度）、调参资产的 Inspector |

### 6.2 增长规则

1. **六层和 Sim 的四个领域是固定的。**新增层或领域必须先修改本文件。
2. **领域内部不开子目录。**东西多了就拆文件，不拆目录。一个领域超过约 20 个文件时，先检查是不是有东西放错了领域，再讨论是否修改划分。
3. **枚举和事件就近定义**：写在使用它的领域文件里，不建单独的 `Enums/`、`Events/` 目录。Game 层自己的事件写在 Game 里。
4. **调参只加字段，不加资产类型**（见 5.1）；内容资产类型只有两种（见 5.2）。
5. Core、Game、Tests、Editor 保持平铺。

## 7. 对已复制代码的调整

- `Core/EventBus/`、`Core/StateMachine/` 两个子目录合并到 `Core/` 平铺。
- 删除空的 `Core/EventBus/Events/`。
- 为 Core 建立 `Fogline.Core` asmdef。
- 面包店 `EventBus.Emit` 里的编辑器日志保留，但模拟每步的高频事件需要过滤，避免刷屏。

## 8. 测试策略

| 测试 | 内容 |
| --- | --- |
| 领域规则 | 例如：深度与雾压换算；结构推导；造价；道岔与沿边移动；受力与牵引力上限；声音遮挡；猎手的阶段转移、硬直与搁浅；三角定位收敛 |
| 平衡检查 | 读取林芝 Scenario 与调参资产，用航线估算器计算每趟委托每条路线在三个潮位下的消耗，断言 mvp 第 5.5 节的四条 |
| 确定性 | 同一指令序列跑两次，结果完全相同（快照和回放的前提） |
| 程序集约束 | 扫描 `Fogline.Sim`，禁止出现 MonoBehaviour、GameObject、`Time`、`SceneManager`、ServiceManager、EventBus |

模拟中的随机数使用 `SimWorld` 持有的带种子的随机数生成器，不使用 `UnityEngine.Random`。

## 9. 与 demo 实现顺序的对应

mvp 第 10 节的九步落在各部分的情况：

| 步骤 | 主要涉及 |
| --- | --- |
| 1. 驾驶原型 | Sea（高度图、深度）、Network（图、段、道岔）、Train（操纵与受力）、View/Chart、View/Cockpit、Editor（轨道编辑工具） |
| 2. 环境与生存 | Sea（潮汐、潮流）、Train（能源、噪音、雾压）、Chart（时间轴预测） |
| 3. 侦测与声音 | Sea（声音）、Train（发射器）、Chart（声纳、接触目标） |
| 4. 猎手 | Sea |
| 5. 站点循环 | Network（站点、委托）、Train（格子）、View/Station |
| 6. 开辟 | Network（造价）、Train（施工） |
| 7. 雾航通告 | Chart |
| 8. 内容 | Data/Scenarios、Editor |
| 9. 试玩支持 | Game（日志、问卷） |
